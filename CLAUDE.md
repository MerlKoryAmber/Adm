# CLAUDE.md — правила проекта admanager

Язык проекта — **русский** (ответы, docs, коммиты). Стиль ответов — краткий, без воды, смысл сохранён (§13).

## Основные правила (22 пункта)

1. **Разделение ролей.** Проектировщик, строитель, проверяющий, приёмщик — разные агенты/люди. Автор кода себе «принято» не ставит.
2. **Пайплайн крупной задачи.** АУДИТ → ПЛАН (согласовать) → РЕАЛИЗАЦИЯ (по плану) → ВЕРИФИКАЦИЯ (другим) → ПРИЁМКА (человеком). Статусы: НЕ НАЧАТА → В РАБОТЕ → РЕАЛИЗОВАНО НО НЕ ПРИНЯТО → ПРИНЯТО → ЗАБЛОКИРОВАНО.
3. **Завершённость.** Перед «готово»/сменой темы — попунктная сверка с формулировкой задачи. Хвосты — явно в трекер (≥2 пунктов → сразу в трекер).
4. **Верификация независимыми агентами.** Ревью кода + аудит безопасности + тесты (покрытие+регресс, гейт зелёный) + UI-верификация в браузере (не автором, со скриншотами). «Готово» без отчётов проверок не бывает.
5. **Массовые изменения.** Baseline → dry-run (посчитать, не трогая) → регресс → apply с бэкапом → post-check запросом к данным. Число строк не сошлось с dry-run → откат.
6. **Коммиты и ветки.** Точечный коммит, явный список файлов; никогда `git add .`. Код в `feature/…`/`fix/…`, слияние в main по команде человека; docs можно в main сразу. Перед push обновить README.md, CHANGELOG.md, docs/handoff/CURRENT.md, docs/SKELETON.md (если менялись). Секреты/.env/дампы не коммитить.
7. **Сохранение коммитов.** Ни один коммит не теряется. Периодический аудит `rev-list`/`stash list`/`status`.
8. **Параллельные сессии.** Перед правками `git fetch` + сверка main и чужих веток. Общий счётчик занимается в общей ветке сразу.
9. **Конфликты решает агент** в ветке `reconcile/<задача>`, main и чужие не трогаются. Одинаковый смысл с двух сторон — не склеивать, человеку оба варианта. Провал тестов → ЗАБЛОКИРОВАНО.
10. **Документы важнее памяти.** Решения — в файлах репо. Архитектура — в ADR (`docs/adr/README.md`). Синк docs перед push обязателен.
11. **Отчёты и промпты.** Один промпт — один шаг. Полный отчёт — в `docs/agent_reports/<задача>/REPORT.md`, в чат 5–8 строк.
12. **Субагенты** — для независимых ветвей, широкого аудита, верификации не автором, долгих прогонов. Параллельно; отчёт в общую верификацию.
13. **Стиль.** Ответы терпко, без воды. Коммиты Conventional Commits (тип латиницей, текст после `:` по-русски). Предупреждения безопасности и необратимое — обычным языком.
14. **Скиллы.** Есть подходящий скилл — прочитать перед первым действием. При конфликте этот CLAUDE.md и владелец выше скилла.
15. **Вопросы человеку** — только формой с вариантами + пояснение (последствия) у каждого. Рекомендуемый — первый. Без прозы.
16. **Не придумывать.** Сначала docs и код проекта, переиспользовать паттерны, стандартные библиотеки > самопис. Новое — только по согласованию.
17. **Локальные операции** без спроса: `git pull`/`fetch`, локальные тесты, установка зависимостей. Разрушительное (push, деплой, удаление, отправка наружу) — с подтверждением.
18. **Уборка диска.** Свои временные артефакты удалять, работать в scratchpad. Файлы пользователя и данные проекта не трогать.
19. **Приёмка.** «Принято» ставит только человек; агент задачу сам не закрывает. После принятого — обновить доки.
20. **Время — МСК (UTC+3).** Любое время в ответах/отчётах/ADR/именах файлов — МСК. Иная зона — перевести с пояснением: `14:20 МСК (11:20 UTC)`.
21. **UX админки.** Русские подписи + пояснение под полем. Фиксированный набор → checkbox/radio/select; свободный ввод только для произвольного (хост, порт, email, TTL). Новое поле → человекочитаемая форма. Никаких браузерных `alert`/`confirm`/`prompt` — UI-ошибки и confirmDialog.
22. **SKELETON.md.** `docs/SKELETON.md` — актуальная структурная карта (файлы+роли, модель, эндпоинты, интерфейсы, паттерн сущности). Читать перед задачей, обновлять перед push. Код прав — скелет чинить. Перед реализацией оценить, можно ли улучшить схему.

## Специфика admanager

| Параметр | Значение |
|----------|----------|
| **Назначение** | Веб-панель управления и делегирования управления on-prem **AD** и **Exchange 2019**. Аналог ManageEngine ADManager Plus, суженный до management + delegation + automation. |
| **Язык/стек** | C# / .NET 8, Blazor Server, EF Core + SQL Server. Вход техников — Windows Auth (Kerberos SSO). |
| **AD** | `System.DirectoryServices.Protocols` + `AccountManagement`. Топология MVP — один домен, один лес. |
| **Exchange** | Только remote PowerShell (`System.Management.Automation`), пул runspace-ов, Kerberos. Нативного API у Exchange нет. |
| **Operational identity** | По умолчанию **gMSA** (без хранимого пароля), спрятана за `IOperationalCredentialProvider`. Альтернатива — хранимая зашифрованная доменная УЗ (модель ADManager). Никогда не Domain Admin — точечная делегация прав. |
| **Делегирование** | Модель ADManager: Технич (HDT) → Роль (набор задач) → Scope (OU/группа) → портал техника. Операции выполняет operational identity, не техник (нет double-hop). |
| **Automation** | Есть (scheduler + rule engine, `BackgroundService`). **Апрув-workflow не делаем.** Каждая авто-операция идёт через тот же core + RBAC + аудит (actor = «Automation: <политика>»). |
| **Аудит** | Неизменяемый журнал всех операций (кто, что, над кем, когда, было/стало). |
| **Архитектура** | Clean/onion: `Web → Application → Domain`; все `Infrastructure.*` реализуют интерфейсы `Application`. |
| **Статус** | Скелет, не продакшен. |

**Язык UI:** приложение — **на английском**; полная поддержка **Unicode** (кириллические УЗ, OU, атрибуты AD/Exchange). §21 действует по механике (select/radio для фикс-наборов, без браузерных alert/confirm), но подписи — **английские**. Чат/docs/коммиты остаются на русском.

**Коммиты:** Conventional Commits, тип латиницей, текст после двоеточия по-русски.

**Запрещено:** давать operational identity избыточные права (Domain Admin); олицетворять техника при операциях; пушить без актуализации `docs/handoff/CURRENT.md` и `docs/SKELETON.md`.

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
